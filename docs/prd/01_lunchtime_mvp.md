## 1. 제품 목표

LunchTime은 회사 구성원이 점심 가게별 모집을 발견하고, 참여하고, 자신의 메뉴를 빠짐없이 전달하며, 주문 상태를 확인할 수 있게 하는 macOS 앱입니다.

자유로운 대화는 유지하되 주문에 필요한 가게, 참여자, 개인 메뉴, 마감과 주문 상태는 구조화합니다. 별도 중앙 서버를 운영하지 않고 회사 내부망의 피어(Peer)들이 각자 보유한 데이터를 교환해 현재 상태를 복구합니다.

### 가장 중요한 실패

참여자가 메뉴를 제출했는데 다른 참여자, 특히 실제 주문하는 사람이 이를 인식하지 못해 주문에서 누락되는 상황을 최우선으로 방지합니다.

완전한 중앙 정본이 없는 구조에서는 모든 네트워크 단절 상황의 무손실을 보장할 수 없습니다. 따라서 MVP는 다음 원칙을 지켜야 합니다.

1. 메뉴 변경을 로컬에 반영했다는 사실과 다른 피어에 전달됐다는 사실을 구분합니다.
2. 아직 공유되지 않았거나 최신 여부를 확인할 수 없는 메뉴를 성공한 것처럼 표시하지 않습니다.
3. 주문 전에 참여자와 메뉴를 다시 동기화하고, 누락 가능성이 있는 상태를 명확히 알립니다.
4. 잠자기·네트워크 단절에서 돌아오면 자동으로 차이를 수집하고 수동 새로고침도 제공합니다.

### 제품 가치 신호

- Slack을 다시 탐색하지 않고 오늘의 모집과 주문 상태를 파악할 수 있습니다.
- 참여자가 제출한 개인 메뉴의 누락과 재확인 횟수가 줄어듭니다.
- 생성부터 참여, 메뉴 제출, 주문 상태 확인과 14:30 종료까지의 흐름이 완주됩니다.
- 과거 가게 기록을 이용해 반복 모집을 더 빠르게 시작합니다.
- 지원 네트워크 안에서 동기화 실패를 인지하고 복구할 수 있습니다.

## 3. MVP에서 제외하는 것

- Windows 클라이언트
- CLI 인터페이스(D-23, C-06, F-60)
- 가게 후보 목록, 투표와 투표를 통한 최종 가게 확정(F-29~F-32)
- 가게명과 별개인 사용자 정의 방 제목·모집 메뉴·메모(F-10)
- QR 이외의 AirDrop, 시스템 공유 시트 등 추가 휴대폰 전달 방식(F-27)
- 배민의 비공개 API 또는 스크래핑을 이용한 메뉴 조회(D-12)
- LunchTime 안에서의 실제 주문, 결제와 배달 상태 추적
- 주문 완료 이후의 `출발` 상태
- 새 방, 주문 마감과 주문 완료 시스템 알림
- 11:00 전사 점심 선택 알림(D-25, F-74)
- MenuBar의 라운지 바로가기, 라운지 읽지 않음과 메시지 알림(D-24, F-48)
- Mac이 잠자기 또는 전원 꺼짐 상태일 때의 실시간 통신·알림 보장
- 중앙 서버를 전제로 한 계정, 푸시 알림과 영구 백업
- 같은 사람의 여러 Mac을 하나의 사용자 권한으로 연결하거나 기기 사이에 권한을 이전하는 계정 기능
- 배민 링크 형식·도메인 검증과 잘못된 링크 경고
- 지원 사내 Wi-Fi 내부의 악의적인 LunchTime 피어 탐지·격리
- 취소됐거나 최종화가 불완전한 방을 성공 가게 히스토리에 반영하는 동작
- 채팅의 영구 보존, 무손실 전달, 읽음 확인과 모든 피어 수신 보장
- 피어 수동 승인·신뢰 관리 화면과 연결 화면의 변경별 ACK 상세

## 4. 용어와 핵심 모델

| 용어 | 정의 |
|------|------|
| 운영일 | `Asia/Seoul` 기준 한 날짜의 11:00~14:30 점심 운영 구간. 쓰기는 14:30에 종료합니다. |
| 점심방(Room) | 가게 하나와 그 배민 링크를 중심으로 참여자, 개인 메뉴, 주문 상태와 채팅을 묶는 공간 |
| 참여 | 사용자가 해당 가게의 공동 주문에 포함되겠다는 의사 표시. 요청 기기가 마감 전에 유효한 참여 수락 ACK를 받아야 확정됩니다. |
| 주문 마감 시각 | 방 생성 시 11:00 이상 14:30 미만에서 정하는 신규 참여 종료 시각 |
| 주문 완료 | 실제 배민 주문이 접수됐음을 참여자가 표시한 가역 상태 |
| 쓰기 종료 | 14:30에 일어나며 신규 이벤트 작성을 막는 비가역 일일 경계 |
| 최종화 | 활성 기기에서는 14:30부터 14:32까지, 경계에 잠든 기기에서는 다음 실행·깨우기부터 최대 120초 동안 14:30 이전 이벤트를 대조해 종료 스냅샷을 만드는 과정 |
| 취소된 방 | 생성자 취소 또는 마지막 참여자 철회로 종료되어 최근 방 상세와 가게 히스토리에서 제외되는 방 |
| 라운지 | 특정 점심방과 무관한 잡담을 위한 별도 채팅 공간 |
| 운영 데이터 | 방, 참여, 메뉴, 상태와 이를 재구성하는 피어 동기화 데이터 |
| 가게 히스토리 | 반복 모집을 위해 로컬에 장기 보존하는 가게명, 배민 링크와 최근 이용 정보 |
| 최근 방 상세 | 취소되지 않은 방의 최종 또는 `종료 · 동기화 불완전` 스냅샷을 자동 신뢰된 사내망 피어가 최대 14일 동안 보는 열람 전용 기록 |
| 종료 · 동기화 불완전 | 최대 120초 최종화 안에 필요한 대조를 끝내지 못한 사용자 표시 상태. 열람과 후속 제한 동기화는 허용하지만 성공 히스토리는 만들지 않습니다. |
| 인식된 피어 | 지원 사내 Wi-Fi에서 발견되어 자동 신뢰되고 데이터를 읽고 교환할 수 있는 LunchTime Mac 클라이언트 |
| 정상 응답 피어 | [POL-02-R-03](../policies/02_replication_consistency_retention.md)에서 정의한, 현재 세션의 유효 응답 범위에 포함되는 인식된 피어 |
| 사용자 ID | 설치 시 생성해 기기 키에 결합하는 불투명 권한 식별자. MVP에서는 설치·기기 하나와 1:1이며 닉네임과 구분합니다. |
| 닉네임 | 피어 목록과 참여자 화면에 보이는 이름. 중복을 허용하고 권한 판정에는 사용하지 않습니다. |

참여자가 한 명뿐인 방도 유효하며 주문 완료, 14:30 쓰기 종료와 최종화까지 정상적으로 진행할 수 있어야 합니다. `한 사용자`와 본인 소유권은 닉네임이 아니라 사용자 ID로 판정합니다. 한 사용자 ID는 같은 운영일에 하나의 방에만 참여할 수 있으며, 주문 상태가 `진행 중`일 때 현재 방에서 참여를 철회한 뒤 다른 방으로 이동하거나 새 방을 만들 수 있습니다.

## 5. 사용자 경험

### 5.1 메뉴 막대(MenuBar)

메뉴 막대는 오늘 상황을 빠르게 확인하고 앱 창을 여는 진입점입니다.

MVP에서 각 활성 방에 다음 정보를 표시합니다.

- 가게명
- 참여자 수
- 참여 모집 중, 주문 마감과 주문 완료를 구분하는 상태 아이콘
- 선택한 방을 별도 앱 창에서 여는 동작
- 새 방을 만들거나 전체 앱 창을 여는 동작
- 마지막 동기화 시각과 주의가 필요한 연결 상태

채팅, 긴 메뉴 입력과 히스토리 관리는 메뉴 막대 안에서 수행하지 않습니다. 당일 방은 14:30에 메뉴 막대에서 제거합니다.

### 5.2 앱 창

별도 앱 창은 다음 영역을 제공합니다.

- 오늘의 점심방 목록과 선택한 점심방 상세
- 새 점심방 생성
- 참여자와 개인 메뉴 목록
- 방별 채팅
- 배민 링크 QR
- 주문 상태 변경
- 히스토리와 재모집
- 최근 14일 방 상세 열람
- 라운지
- 연결·동기화 상태 및 수동 새로고침
- 연결된 피어 목록

### 5.3 QR 표시와 휴대폰 스캔

입력 링크가 등록된 방은 QR 코드를 표시합니다. 사용자는 Mac 화면의 QR을 휴대폰으로 스캔할 수 있습니다. LunchTime은 입력 문자열의 QR 생성·표시까지만 책임지며, 스캔 뒤 배민 앱이나 페이지가 실제로 열리는지는 보장하지 않습니다.

- QR에는 사용자가 입력한 배민 링크 문자열을 변환·정규화하지 않고 그대로 담습니다.
- MVP는 링크 형식이나 도메인을 검증하지 않으며 링크가 잘못됐다는 경고도 제공하지 않습니다. QR 렌더링 자체가 실패한 경우에만 QR을 표시할 수 없음을 알립니다.
- LunchTime은 링크 이후의 배민 앱 동작을 제어하거나 주문 성공을 추론하지 않습니다.

### 5.4 최근 방 상세

최근 방 목록은 재모집용 가게 히스토리와 구분합니다. 자동 신뢰된 사내망 피어는 취소되지 않은 방을 선택해 최대 14일 동안 구조화된 최종 상태 또는 `종료 · 동기화 불완전` 상태를 열람할 수 있습니다.

- 가게명·배민 링크, 최종 주문 상태, 참여자와 개인 메뉴 스냅샷, 주요 시스템 이벤트 및 최종화 완전성을 표시합니다.
- 방 참여 여부와 관계없이 자동 신뢰된 사내망 피어가 평문 상세를 열람할 수 있습니다.
- 늦은 재연결에서 14:30 이전의 유효 이벤트를 더 받으면 스냅샷을 다시 계산할 수 있으며, 화면에 마지막 재계산 시각을 표시합니다.
- 사용자는 최근 방 상세에서 수동 새로고침으로 새 제한 동기화 세션을 시작할 수 있습니다.
- 어떤 값도 수정할 수 없으며, 재모집은 별도의 가게 히스토리에서 시작합니다.
- 취소된 방은 최근 방 목록에 표시하지 않습니다.
- 앱 종료 시 삭제된 방 채팅은 최근 방 상세에 복원하거나 영구 기록하지 않습니다.

### 5.5 연결 화면

연결 화면은 Peer별 닉네임, 온라인 여부, 마지막 확인 시각과 동기화 상태만 표시합니다. 같은 닉네임이 둘 이상이면 로컬에서 안정적인 짧은 접미사를 붙여 구분합니다. 신뢰 여부, 개별 변경 ACK와 암호화 키 정보는 이 화면에 표시하지 않습니다.

## 6. 기능 요구사항

### PRD-01-FR-01. 일일 라이프사이클

1. 앱은 기기 locale·time zone과 무관하게 `Asia/Seoul` 업무 달력을 사용하고, 당일 쓰기 기능은 KST 11:00부터 활성화합니다. 장부 저장과 Peer 교환의 절대 시각은 UTC instant로 표현하며, KST 변환은 업무 달력 판정과 사용자 표시에만 사용합니다.
2. 방 생성 시 주문 마감 시각을 필수로 입력하며, 현재 시각 이후이면서 14:30보다 빨라야 합니다.
3. 주문 마감 시각이 되면 신규 참여만 닫습니다.
4. 기존 참여자는 14:30 전까지 방 열람과 방 채팅을 계속할 수 있습니다. 자신의 메뉴는 주문 상태가 `진행 중`일 때만 관리할 수 있습니다.
5. 매일 14:30에 당일 이벤트 쓰기를 막고 당일 방을 메뉴 막대에서 제거한 뒤 백그라운드 최종화를 시작합니다. 현재 앱 세션에서는 방과 라운지 창을 메모리 내용의 열람 전용 화면으로 계속 열 수 있습니다.
6. 최종화는 14:30 이전에 생성된 이벤트만 받아 14:32까지 최대 120초 동안 대조합니다. 제한 안에 필수 최신 리비전을 확인하면 최종화를 완료하고, 확인하지 못하면 사용자 상태를 `종료 · 동기화 불완전`으로 기록합니다.
7. 14:30에 잠자기·종료 상태였던 기기는 다시 실행되거나 깨어나는 즉시 쓰기를 재개하지 않고 그 시점부터 최대 120초 동안 최종화를 수행합니다. 보존 중인 14:30 이전 이벤트를 나중에 더 받으면 최근 방 스냅샷을 다시 계산할 수 있습니다.
8. 14:30 이후에는 당일 방을 쓰기 가능한 활성 상태로 다시 열거나 생성·참여·수정·채팅·상태 변경할 수 없습니다. 현재 앱 세션의 방·라운지 채팅은 열람 전용 창에서 읽을 수 있고, 구조화된 종료 결과는 최근 방 상세에서도 확인합니다.
9. 활성 데이터의 주기적 반엔트로피(anti-entropy)는 14:30에 중단합니다.
10. 앱은 macOS 시스템 시각을 MVP의 현재 시각 기준으로 사용합니다. 어떤 Peer와도 공유되지 않은 local-only Room은 이 기준만으로 시간 의존 쓰기를 판정할 수 있지만, 한 번이라도 공유된 Room은 fresh한 정상 응답 Peer 대조가 없거나 시각이 충돌하면 시간 경계 쓰기를 안전하게 차단합니다. 사용자는 차단 이유·복구 방법·종료 결과를 확인할 수 있어야 하며, 정확한 범위와 실패 시 안전 차단(fail-closed) 처리는 [POL-02-R-08](../policies/02_replication_consistency_retention.md)을 따릅니다.
11. 11:00 전사 알림은 MVP에서 제공하지 않습니다.

추적: D-08, D-10, D-13~D-14, D-31, D-38~D-39, F-11, F-17, F-40, F-64, F-74

### PRD-01-FR-02. 점심방 생성과 참여

1. 새 방에는 가게명을 필수로 입력합니다.
2. 배민 링크와 주문 마감 시각을 함께 필수로 입력합니다.
3. 방은 가게 하나만 가집니다. 후보 가게와 투표 단계는 두지 않습니다.
4. 생성자는 생성과 동시에 참여자로 등록합니다.
5. 같은 운영일에 여러 방이 존재할 수 있습니다.
6. 방은 참여자가 한 명뿐이어도 유효합니다.
7. 신규 참여는 요청 기기가 주문 마감 전에 유효한 수락 ACK를 받은 경우에만 확정합니다. 마감 전에 참여를 요청했더라도 요청 기기가 마감 전까지 ACK를 받지 못하면 참여하지 않은 것으로 처리합니다.
8. 마감 전에 ACK를 받아 이미 확정된 참여 이벤트는 마감 뒤 다른 Peer에 도착해도 유효하며 참여자와 메뉴 상태에 반영합니다.
9. 인식된 Peer는 현재 참여자 목록과 각 참여자의 메뉴 제출·동기화 상태를 읽을 수 있습니다.
10. 사용자는 하루 한 방 참여를 유지하며, 중복 참여가 발견되면 자동 선택 대신 `확인 필요`에서 직접 유지할 방을 선택합니다. 선택 전에는 주문 누락 위험이 있는 쓰기와 주문 완료를 제공하지 않습니다.
11. 방 정보의 변경·참여 철회·취소는 권한과 주문 상태에 따라 허용 또는 잠기며, 사용자는 변경 불가 이유와 취소된 방의 열람 전용 결과를 확인할 수 있어야 합니다.
12. 참여·생성자·취소·마감·중복 참여의 정확한 권한·상태 전이·무효화 규칙은 [POL-01-R-02](../policies/01_daily_room_lifecycle.md), [POL-01-R-04](../policies/01_daily_room_lifecycle.md), [POL-01-R-05](../policies/01_daily_room_lifecycle.md), [POL-02-R-05](../policies/02_replication_consistency_retention.md)을 따릅니다.

추적: D-21, D-26, D-29, D-33, D-40~D-41, F-09, F-11~F-15, F-17~F-18, F-22~F-24, C-05

### PRD-01-FR-03. 개인 메뉴

1. 참여자는 자신에게 귀속된 메뉴 항목을 한 개 이상 등록할 수 있습니다.
2. 각 메뉴 항목의 입력 구조는 다음과 같습니다.

| 필드 | 필수 여부 | 규칙 |
|------|-----------|------|
| 메뉴명 | 필수 | 한 줄 텍스트 |
| 옵션 | 선택, 여러 개 | 옵션 한 개당 한 줄 텍스트 |

3. 자유 형식의 여러 줄 텍스트 한 덩어리 대신 위 구조를 고정된 폼으로 제공합니다.
4. 참여자는 자신의 메뉴를 관리할 수 있고, 주문 상태·시간 경계·동기화 충돌로 변경할 수 없을 때 그 이유를 확인할 수 있어야 합니다. 정확한 권한과 상태 전이는 [POL-01-R-05](../policies/01_daily_room_lifecycle.md)를 따릅니다.
5. 참여자별 메뉴를 한 화면에서 주문용 목록으로 확인하고 복사할 수 있습니다. 누락·대기·충돌 상태가 있으면 복사를 비활성화하고 이유를 표시합니다.
6. 모든 메뉴 생성·수정에는 고유 변경 ID와 작성 Peer를 부여해 중복 또는 누락 여부를 추적할 수 있어야 합니다.
7. `이 기기에 저장됨`, `복제됨`, `동기화됨`, `확인 필요`의 네 안정 상태를 구분해 표시합니다. 교환 중에는 별도 안정 상태를 만들지 않고 일시적인 `동기화 중` 진행 표시를 덧붙입니다.
8. 옵션 안의 금액 표기는 문자열의 일부로 보존하며 MVP에서 가격을 별도 계산하거나 검증하지 않습니다.
9. 활성 Room의 메뉴 가시성과 쓰기 범위는 [POL-03-R-01](../policies/03_security_and_trust.md)을 따릅니다.

예시:

```text
메뉴명: 다운타우너 버거 세트
옵션:
- 오리지널 프라이즈 / +2,000원
- 코카콜라 제로 255ml
- 싱글
```

추적: D-07, D-32, D-35, F-34~F-37, F-50, F-55, F-58

### PRD-01-FR-04. 방별 채팅

1. 각 점심방은 해당 주문 협의를 위한 채팅을 제공합니다.
2. 채팅은 구조화된 가게·참여·메뉴 정보를 대체하지 않습니다.
3. 인식된 피어는 활성 방 채팅을 읽을 수 있지만 메시지 작성은 해당 방의 현재 참여자만 할 수 있습니다. 참여가 마감된 뒤에도 기존 참여자는 14:30까지 메시지를 주고받을 수 있습니다.
4. 14:30 이후에는 방 채팅 입력을 제공하지 않습니다. 현재 앱 세션의 메모리에 남은 채팅은 열람 전용 방 창에서 읽을 수 있고 앱 종료 뒤에는 복원하지 않습니다.
5. 채팅 데이터는 메모리에서만 관리하며 앱 종료 시 해당 기기에서 삭제합니다.
6. 앱 재시작 시 현재 활성 일일 세션에 한해 연결 가능한 Peer가 메모리에 보유한 당일 메시지를 다시 받을 수 있지만, 모든 Peer에서 삭제된 메시지의 복구는 보장하지 않습니다.
7. 각 메시지에는 전역적으로 충돌 가능성이 낮은 메시지 ID, 방 ID, 작성 사용자·피어와 논리적 순서 정보를 포함합니다.
8. 같은 메시지 ID는 한 번만 표시합니다. 논리적 순서를 먼저 적용하고 순서가 같은 메시지는 메시지 ID로 결정적으로 정렬하며, 늦게 받은 메시지는 정해진 위치에 삽입할 수 있습니다.
9. 메시지 전송과 재수신은 최선형(best-effort)이며 영구 전달이나 모든 피어 수신을 보장하지 않습니다. 전송·복구 진행과 마지막 동기화 시각은 표시합니다.

추적: D-04, D-13, D-19, D-35, D-37, F-19~F-21, F-51, F-62, F-69

### PRD-01-FR-05. 주문 상태

1. 실제 주문 뒤 참여자는 Room을 `주문 완료`로 표시하고, 14:30 전 주문 취소·재주문 상황에서는 되돌린 결과를 참여자에게 보여줄 수 있어야 합니다.
2. 주문 완료·되돌리기·취소가 가능한 사용자와 상태, 잠기는 동작, 기록과 시간 경계는 [POL-01-R-04](../policies/01_daily_room_lifecycle.md), [POL-01-R-05](../policies/01_daily_room_lifecycle.md)를 따릅니다.
3. `출발` 상태는 두지 않습니다.

추적: D-09, D-10, D-31, D-33, F-38~F-40, F-73

### PRD-01-FR-06. 주문 전 누락 확인

주문 완료 동작을 실행하기 전에 다음 요약을 보여줍니다.

- 참여자 수와 명단
- 메뉴를 제출한 참여자와 제출하지 않은 참여자
- 각 메뉴의 마지막 변경 시각과 동기화 상태
- 현재 연결된 피어 수와 마지막 전체 대조 시각
- 현재 참여자의 최신 리비전 보유 여부
- 아직 전파 중이거나 충돌 해결이 필요한 항목

동기화되지 않은 변경, 메뉴 미제출 참여자 또는 충돌이 있으면 경고와 새로고침 동작을 제공하고 주문 완료를 막습니다.

- 다인 방에서는 각 현재 참여자의 최신 참여·메뉴 리비전이 최소 한 대의 다른 인식된 Peer에 복제되고, 주문 완료를 실행하는 기기가 ACK된 최신 리비전을 모두 보유해야 합니다.
- 과거에 방 이벤트를 보유하거나 ACK했지만 현재 오프라인인 피어는 위 조건을 충족한 경우 주문 완료를 막지 않습니다.
- 해당 방과 무관하거나 같은 방 요약을 보유하지 않았다고 확인된 피어의 미대조·미응답도 주문 완료를 막지 않습니다. 현재 정상 응답 피어가 더 최신이거나 서로 다른 방 요약을 알린 경우에만 대조가 끝날 때까지 막습니다.
- 단일 참여자 방의 ACK 없는 완료는 생성자만 참여하고 어떤 방 이벤트도 다른 피어와 공유하거나 ACK받은 적이 없는 방에만 허용합니다. 사용자는 로컬 최신 리비전을 직접 확인해야 합니다.
- 한 번이라도 다른 Peer와 공유된 Room은 현재 단일 참여자이고 다른 Peer가 오프라인이어도 ACK 없는 완료 예외를 적용하지 않습니다.
- 다인 방에는 누락 위험을 무시하는 강제 완료를 제공하지 않습니다.

추적: D-17, D-30, F-66~F-67

### PRD-01-FR-08. 가게 히스토리와 재모집

1. 히스토리의 목적은 자주 주문하는 가게로 새 방을 빠르게 만드는 것입니다.
2. 히스토리에는 가게명, 배민 링크, 최근 주문 완료 시각과 로컬 이용 횟수를 저장합니다.
3. 채팅, 과거 참여자와 개인 메뉴는 재사용 히스토리에 저장하지 않습니다.
4. 가게 히스토리는 각 사용자의 Mac에 암호화해 저장하며, 14일 운영 데이터 보존과 별개로 사용자가 삭제할 때까지 유지합니다.
5. 피어 연결 시 서로의 가게 히스토리를 합쳐 앱 재시작 또는 기기별 차이를 복구합니다.
6. 같은 가게를 판별하는 키는 `가게명의 양끝 공백 제거 결과`와 `사용자가 입력한 배민 링크 원문`의 정확한 조합입니다. 대소문자, URL 구성요소 또는 링크 문자열을 정규화하지 않습니다.
7. 피어에는 가게명, 배민 링크와 최근 주문 완료 시각만 공유합니다. 이용 횟수는 기기별 로컬 값으로 유지하며 피어 값과 더하거나 덮어쓰지 않습니다.
8. 히스토리의 `다시 모집`을 선택하면 가게명과 배민 링크가 채워진 방 생성 화면을 엽니다.
9. 사용자가 주문 마감 시각과 복사 내용을 확인한 뒤 방을 생성합니다. 이전 참여자와 개인 메뉴는 복사하지 않습니다.
10. 가게 히스토리에는 `주문 완료` 상태로 finalization이 완료된 Room만 성공 이용으로 반영합니다. 취소됐거나 `종료 · 동기화 불완전`인 Room은 반영하지 않습니다.

### PRD-01-FR-09. 피어 발견과 동기화

1. 사용자는 지원 사내 Wi-Fi에서 발견한 Peer와 중앙 리더 없이 변경을 교환하고, 생성자가 떠난 뒤에도 다른 Peer가 보유한 Room을 계속 사용할 수 있어야 합니다.
2. 잠자기 복귀, 앱 전면 전환, 네트워크·피어 변화, 로컬 변경 및 수동 새로고침은 사용자에게 최신 상태를 확인할 기회를 제공합니다. 대조가 끝나지 않으면 성공으로 표시하지 않고 `확인 필요`와 새로고침을 제공합니다.
3. 활성 데이터와 정상 응답 Peer가 모두 있을 때만 주기 대조를 하며, 14:30에는 활성 데이터 주기 대조를 멈춥니다. 정확한 트리거·재시도·시간 한도와 재개 조건은 [POL-02-R-02](../policies/02_replication_consistency_retention.md)를 따릅니다.
4. 발견 범위, 복제 방식, 충돌 수렴과 시간 경계 허용치는 출시 전 기술 스파이크가 정합니다. Peer 시각은 macOS 시스템 시각을 보정하거나 평균·다수결로 대체하지 않고, 공유된 Room의 불일치 탐지와 fresh 교차 확인에만 사용합니다. 기술 스파이크 결과 전에도 불확실한 데이터는 `동기화됨` 또는 주문 가능한 최신 데이터로 표시하지 않습니다. [POL-02-R-01](../policies/02_replication_consistency_retention.md), [POL-02-R-05](../policies/02_replication_consistency_retention.md), [POL-02-R-08](../policies/02_replication_consistency_retention.md)을 따릅니다.

추적: D-02, D-03, D-15~D-16, D-27, D-31~D-32, D-35, F-49~F-55, F-58~F-59, F-63, F-65

### PRD-01-FR-10. 복귀와 최신성 표시

1. 잠자기 또는 네트워크 단절 중의 실시간 동기화는 보장하지 않습니다. 복귀하면 사용자는 자동 대조 진행, 마지막 확인 시각, 확인한 피어 수와 복구·미해소 결과를 확인할 수 있어야 합니다.
2. 사용자는 `이 기기에 저장됨`, `복제됨`, `동기화됨`, `확인 필요`를 구분해 볼 수 있어야 하며, 교환 중에는 기존 상태를 숨기지 않고 `동기화 중`을 덧붙입니다. 각 상태의 판정과 정상 응답 Peer의 범위는 [POL-02-R-03](../policies/02_replication_consistency_retention.md)를 따릅니다.
3. 데이터 공백·인증 또는 복호화 실패·공유된 Room의 시계 대조 부재·시계 차이·충돌을 해소하지 못하면 성공으로 표시하지 않고 원인 안내와 수동 새로고침을 제공합니다. system clock 변경 뒤에는 기존 시계 대조를 재사용하지 않으며, local-only Room과 공유된 Room의 복구 차이는 [POL-02-R-08](../policies/02_replication_consistency_retention.md)을 따릅니다.
4. 연결 화면은 Peer별 닉네임, 온라인 여부, 마지막 확인 시각과 동기화 상태만 표시합니다. 표시 범위와 보존은 [POL-02-R-07](../policies/02_replication_consistency_retention.md), 식별·권한은 [POL-03-R-02](../policies/03_security_and_trust.md)를 따릅니다.

추적: D-32, D-35, D-38, D-43, F-21, F-53~F-54, F-58, F-62~F-63

### PRD-01-FR-11. 데이터 보존

1. 사용자는 방·참여·메뉴·상태의 종료 상세와 재사용 가게 히스토리를 구분해 볼 수 있어야 합니다. 종료 상세는 제한된 기간의 열람 전용이고, 재사용 히스토리는 최소 가게 정보만 사용합니다.
2. 앱 종료 뒤 채팅의 영구 복구를 약속하지 않으며, 취소 방은 최근 방 상세와 성공 가게 히스토리에 표시하지 않습니다.
3. `종료 · 동기화 불완전` 방은 확인 가능한 상세를 보이되 성공 가게 히스토리에 반영하지 않습니다. 유효한 늦은 이벤트가 있으면 열람 전용 스냅샷을 다시 계산하고 결과를 표시합니다.
4. 보존 기간, 삭제·고아 데이터, 채팅 메모리 경계, 최근 방·히스토리 재계산의 정확한 규칙은 [POL-02-R-06](../policies/02_replication_consistency_retention.md)을 따릅니다.

### PRD-01-FR-12. 데이터 보호

1. 사용자는 지원 사내 Wi-Fi에서 자동 신뢰한 피어와만 데이터를 교환하며, 전송·저장 데이터를 보호한 상태로 방을 사용할 수 있어야 합니다.
2. 인증·무결성 또는 복호화에 실패한 데이터는 적용하거나 성공 동기화로 표시하지 않고 `확인 필요`와 안내를 제공합니다.
3. 자동 신뢰는 강한 개인 인증이 아니며, 자동 신뢰된 내부 악성 피어의 평문 열람과 허용 권한 안의 악성 동작은 MVP 보호 범위 밖임을 사용자에게 오해 없이 표시합니다.
4. 지원 네트워크 경계, 읽기·쓰기 권한, 기기 식별·키 관리, 암호화·QR·로그·클립보드 규칙과 출시 보안 게이트는 [POL-03-R-01](../policies/03_security_and_trust.md)부터 [POL-03-R-07](../policies/03_security_and_trust.md)을 따릅니다.

## 7. 동기화 제품 계약

MVP는 피어별 로컬 장부와 변경 교환을 이용한 **최종 일관성**을 목표로 합니다. 비트코인과 토렌트는 중앙 정본 없이 각 참여자가 데이터를 보유하고 교환한다는 개념적 참고일 뿐, 블록체인·채굴·전역 합의 자체를 구현 요구사항으로 삼지 않습니다.

사용자는 로컬 반영, 다른 피어에 복제됨, 현재 세션에서 대조됨 및 확인이 필요한 상태를 구분해 보고, 데이터 공백을 성공으로 오인하지 않아야 합니다. 이벤트 식별·검증, 충돌, 정상 응답 피어와 상태 판정의 정본은 [POL-02-R-01](../policies/02_replication_consistency_retention.md), [POL-02-R-03](../policies/02_replication_consistency_retention.md), [POL-02-R-05](../policies/02_replication_consistency_retention.md)에 둡니다.

## 8. 수용 시나리오

### PRD-01-AC-01. 단일 참여자 주문

- 한 사용자가 11:00 이후 방을 만들고 자동 참여됩니다.
- 가게명, 배민 링크와 주문 마감 시각을 입력합니다.
- QR에는 입력한 링크 원문이 그대로 인코딩·표시되며 형식·도메인 경고를 제공하지 않습니다. 스캔 뒤 어떤 앱이나 페이지가 열리는지는 수용 조건에 포함하지 않습니다.
- 생성자만 참여하고 어떤 방 이벤트도 다른 피어와 공유하거나 ACK받은 적이 없으면 구조화된 개인 메뉴를 로컬에서 확인하고 ACK 없이 주문 완료할 수 있습니다.
- 위 local-only Room은 현재 process의 유효한 macOS wall-clock·단조 시각 기준점으로 시간 경계를 판정하며, Peer가 없다는 이유만으로 시간 의존 쓰기를 차단하지 않습니다.
- 방이 한 번이라도 다른 피어와 공유됐다면 현재 다른 피어가 오프라인이어도 ACK 없는 단일 참여자 예외를 적용하지 않습니다.
- 14:30에 방 입력과 메뉴 막대 항목을 닫고 현재 앱 세션의 방 창을 열람 전용으로 제공한 뒤 백그라운드 최종화를 시작합니다.

### PRD-01-AC-02. 메뉴 누락 방지

- 두 명 이상이 참여한 방에서 한 참여자가 메뉴를 생성·수정하면 동기화 상태가 표시됩니다.
- 주문 완료 전 요약에 모든 참여자와 메뉴 제출 여부가 나타납니다.
- 아직 동기화되지 않은 메뉴가 있으면 경고와 새로고침 동작이 나타나며 주문 완료가 차단됩니다.
- 다인 방의 각 현재 참여자 최신 참여·메뉴 리비전은 최소 한 대의 다른 인식된 피어가 ACK하고, 주문 완료 기기가 그 리비전을 모두 보유해야 합니다.
- 위 조건을 만족하면 과거에 방 이벤트를 보유하거나 ACK했지만 현재 오프라인인 피어는 완료를 막지 않습니다.
- 누락·대기·충돌 항목을 무시하고 주문 완료하는 우회 동작은 제공하지 않습니다.
- 모든 조건을 통과하면 주문용 메뉴 요약을 복사할 수 있고, 복사 결과는 점검에 사용한 최신 리비전과 일치해야 합니다.
- 지원 네트워크에서 성공적으로 동기화된 메뉴가 주문 요약에서 조용히 누락되는 테스트 케이스가 없어야 합니다.

### PRD-01-AC-03. 잠자기 후 복구

- 한 Mac이 잠자기 상태에서 다른 피어가 참여, 메뉴와 채팅을 변경합니다.
- 잠든 Mac이 깨어나면 별도 재실행 없이 자동 대조를 시작합니다.
- 연결 가능한 피어가 데이터를 보유하면 누락분을 복구합니다.
- 자동 및 수동 대조는 [POL-02-R-02](../policies/02_replication_consistency_retention.md)의 횟수·시간 한도 안에서 끝나며, 한도 소진 뒤 미해소 항목은 `확인 필요`로 표시합니다.
- 교환 중에는 기존 안정 상태에 `동기화 중`을 일시적으로 덧붙이고, 완료 후 네 안정 상태 중 하나와 마지막 동기화 시각을 표시합니다.
- 활성 데이터와 정상 응답 피어가 모두 있을 때의 주기 대조, 새 트리거에 의한 재개, 14:30 이후 복귀·최종화와 오프라인 피어 표시는 [POL-02-R-02](../policies/02_replication_consistency_retention.md), [POL-02-R-06](../policies/02_replication_consistency_retention.md), [POL-02-R-07](../policies/02_replication_consistency_retention.md)을 따른다.
- system clock 변경을 감지하면 기존 시계 검증을 즉시 무효화하고 복구 필요 상태를 앱 재실행 뒤에도 유지합니다. local-only Room은 사용자가 macOS 시각을 점검하고 수동 새로고침으로 새 기준을 만든 뒤 복구할 수 있고, 공유된 Room은 새 기준과 fresh한 정상 응답 Peer 대조를 모두 통과해야 복구합니다.

### PRD-01-AC-04. 앱 재시작

- 앱을 종료하면 해당 기기의 채팅 메모리가 삭제됩니다.
- 재시작 후 방·상태와 가게 히스토리는 로컬 저장소에서 복구됩니다.
- 현재 운영일의 활성 시간이고 연결 가능한 피어가 당일 채팅을 메모리에 보유하고 있으면 다시 동기화합니다.
- 같은 메시지 ID는 한 번만 표시합니다. 동일한 메시지 집합을 보유한 피어는 논리적 순서와 메시지 ID로 같은 결정적 순서를 계산하지만, 메시지 누락으로 인한 전역 순서 일치는 보장하지 않습니다.
- 어떤 피어도 채팅을 보유하지 않으면 복구 불가를 오류가 아닌 허용된 보존 결과로 처리합니다.

### PRD-01-AC-05. 주문 완료 취소와 일일 종료

- 참여자가 주문 완료로 표시한 뒤 14:30 전에는 참여자 누구나 이를 되돌릴 수 있습니다.
- 변경 수행자와 시각이 모든 연결 가능한 피어에 전파됩니다.
- KST 14:30이 되면 주문 상태와 무관하게 쓰기와 메뉴 막대 항목을 막고 현재 앱 세션에서는 방 창을 현재 메모리 내용의 열람 전용 화면으로 제공합니다. 이 terminal close는 system clock rollback이나 기기 time zone 변경으로 다시 열리지 않습니다.
- 백그라운드 최종화는 14:32까지 최대 120초만 수행하고, 필요한 최신 리비전을 확인하지 못하면 `종료 · 동기화 불완전`으로 끝냅니다.
- 자동 신뢰된 사내망 피어는 취소되지 않은 방의 완료 또는 불완전 상세를 열람할 수 있지만, 앱 종료로 삭제된 채팅은 복원되지 않습니다.
- `종료 · 동기화 불완전` 방은 성공 가게 히스토리에 반영하지 않습니다. 14:30 이전 생성과 시계 유효성을 검증할 수 있는 늦은 이벤트로만 최근 방 스냅샷과 완전성을 다시 계산해 성공 히스토리를 생성·복구하거나 기존 성공 레코드를 무효화할 수 있습니다. 이를 검증할 수 없는 늦은 이벤트는 열람용 스냅샷에만 반영하고 성공 결과를 자동 정정하지 않습니다.
- 보존 기간이 끝난 최근 방 상세와 성공적으로 최종화된 최소 가게 히스토리의 처리 결과는 [POL-02-R-06](../policies/02_replication_consistency_retention.md)으로 검증합니다.

### PRD-01-AC-06. 라운지

- 사용자는 별도 앱 창에서 라운지에 들어가 11:00~14:30에 대화할 수 있습니다.
- 점심방 채팅과 라운지 메시지가 섞이지 않습니다.
- 14:30에는 라운지 입력을 닫고 현재 앱 세션에서 메모리의 메시지를 열람 전용 라운지 창으로 볼 수 있게 합니다.
- 앱 종료 시 해당 기기의 라운지 메시지가 삭제됩니다.

### PRD-01-AC-07. 히스토리 재모집

- 과거 가게에서 `다시 모집`을 선택하면 양끝 공백이 제거된 가게명과 입력 당시 링크 원문이 채워진 생성 화면이 열립니다.
- 주문 마감 시각을 확인해야 방을 생성할 수 있습니다.
- 이전 참여자, 개인 메뉴와 채팅은 복사되지 않습니다.
- 가게 히스토리 중복 키는 양끝 공백을 제거한 가게명과 링크 원문의 정확한 조합이며 URL 정규화나 대소문자 변환을 하지 않습니다.
- 취소됐거나 최종화가 불완전한 방은 성공 가게 히스토리에 나타나지 않습니다.

### PRD-01-AC-08. 암호화와 신뢰 경계

- 패킷 캡처에서 LunchTime 응용 데이터가 평문으로 노출되지 않습니다.
- 지원 사내 Wi-Fi에서 발견한 LunchTime 피어는 별도 승인 없이 자동 신뢰됩니다.
- 자동 신뢰된 비참여 피어도 활성 방 메뉴·채팅과 최근 방 상세를 읽을 수 있지만 메뉴·채팅 쓰기는 할 수 없습니다.
- 로컬 저장 파일만 복사해서 방·메뉴·히스토리 원문을 읽을 수 없습니다.
- 연결 화면은 닉네임, 온라인 여부, 마지막 확인 시각과 동기화 상태만 표시하고 신뢰·개별 ACK 정보는 표시하지 않습니다. 중복 닉네임에는 안정적인 접미사를 붙입니다.
- 첫 실행에서 닉네임을 정하기 전에는 피어 노출과 방 쓰기를 허용하지 않으며, 이후 닉네임 변경은 사용자 ID·권한·기존 소유권을 바꾸지 않습니다.
- 명시적 메뉴 복사 전에는 시스템 클립보드에 평문이 남을 수 있고 자동 삭제를 보장하지 않음을 알립니다.
- 자동 신뢰된 내부 악성 피어의 평문 열람과 허용된 권한 안의 악성 동작은 MVP 보호 범위 밖입니다.

### PRD-01-AC-09. 참여 마감과 늦은 전파

- 사용자가 마감 직전에 참여를 요청하고 요청 기기가 마감 전에 유효한 수락 ACK를 받으면 참여가 확정됩니다.
- 이미 확정된 참여 이벤트가 네트워크 지연으로 마감 뒤 다른 피어에 도착해도 참여와 이후 유효한 메뉴를 반영합니다.
- 참여 요청은 마감 전이지만 요청 기기가 마감 전까지 수락 ACK를 받지 못하면 참여를 거부합니다.
- 어떤 Peer와도 공유되지 않은 local-only Room에서 생성자의 시간 의존 동작은 macOS 시스템 시각으로 판정합니다. 원격 참여 수락은 Room을 공유 상태로 전환하는 동작이므로, fresh한 정상 응답 Peer 대조가 없거나 허용 오차를 넘거나 Peer 시각이 충돌하면 이를 차단하고 [POL-02-R-08](../policies/02_replication_consistency_retention.md)의 안내·복구 규칙을 표시합니다.

### PRD-01-AC-10. 마감 수정과 방 취소

- 현재 참여 중인 생성자는 주문이 `진행 중`이고 기존 마감 전일 때만 미래의 14:30 이전 시각으로 마감을 수정할 수 있습니다.
- 가게명과 입력 링크도 현재 참여 중인 생성자가 주문 `진행 중`이고 기존 마감 전일 때만 바꿀 수 있으며 마감 뒤에는 잠깁니다.
- 이미 모집이 마감된 방은 마감을 늦춰 다시 열 수 없습니다.
- 현재 참여 중인 생성자는 `진행 중` 방을 취소할 수 있고, 마지막 참여자가 철회하면 방이 자동 취소됩니다.
- 생성자가 철회해도 다른 참여자가 남아 있으면 방은 유지되고 잔여 참여자는 메뉴·채팅과 주문 완료를 계속할 수 있습니다. 생성자 관리 권한은 재참여해도 복구되지 않고 승계되지 않으며 가게명, 배민 링크와 마감 시각은 잠깁니다.
- `주문 완료` 방은 먼저 완료를 되돌리지 않으면 취소하거나 마지막 참여를 철회할 수 없습니다.
- 취소된 방은 다시 열리지 않고 최근 방 상세와 가게 히스토리에 표시되지 않습니다.

### PRD-01-AC-11. 중복 참여 충돌

- 네트워크 분리 뒤 재동기화에서 같은 사용자의 당일 여러 방 참여가 발견되면 자동 승자를 선택하지 않습니다.
- 사용자가 유지할 방을 직접 선택할 때까지 해당 사용자의 참여·메뉴 쓰기와 관련 방의 주문 완료를 막습니다.
- 선택 뒤 나머지 참여와 메뉴를 무효화하는 이벤트가 전파되고 모든 정상 응답 피어가 같은 결과로 수렴합니다.

기술 검증 결과가 요구한 안정성을 충족하지 못하면 중앙 서버를 임의로 추가하지 않습니다. 지원 범위를 좁히거나 사용자에게 보이는 동작을 재설계하고 제품 결정을 다시 받습니다.

## 10. 출시 전 확정할 지원 범위

제품 방향과 MVP 요구사항은 승인됐습니다. 다음 값은 임의로 정하지 않고 기술 스파이크와 파일럿 증거로 확정합니다.

- `PRD-01-SP-06`에서 초기 파일럿 인원과 최대 지원 피어 수를 측정하고, 이 문서의 성공 기준 표와 출시 게이트에 기록합니다.
- 최소 macOS 버전, SwiftUI/AppKit 경계, 코드 서명과 배포 방식은 앱 기반 작업에서 확정합니다. 이 값은 사용자 결과를 바꾸지 않는 기술 선택이며 별도 출시 검토 증거가 필요합니다.
- 지원 사내 Wi-Fi 판별 구성의 배포 방식은 `PRD-01-SP-01`과 `PRD-01-SP-04` 결과로 확정합니다. 확정 전에는 지원 범위를 추측해 확장하지 않습니다.
- LunchTime 전용 중앙 시간 서버나 별도 외부 시간 서비스는 MVP 범위에 추가하지 않습니다. macOS 자동 시간 설정은 운영상 권장하지만 앱의 runtime 승인 조건으로 검사하지 않으며, OS 시각의 암호학적 진위를 LunchTime이 보장하지 않습니다.
