# 정책 품질 기준

기능과 구현 이슈 전반에서 일관성을 유지해야 하는 규칙을 다룰 때 이 기준을 사용한다.

## 정책이 담당하는 내용

정책은 다음과 같은 규범적 동작을 정의한다.

- 불변식과 신뢰 경계
- 서로 독립적인 상태 축과 전이
- 읽기, 쓰기, 승인, 취소, 복구를 수행할 수 있는 주체
- 검증과 충돌 해결
- 실패, 재시도, 복구, 사용자에게 보이는 성능 저하 상태
- 보존, 삭제, 암호화, 가시성
- 각각은 유효하지만 서로 충돌하는 규칙 사이의 우선순위

정책에서 제품 문제, 기능 홍보 문구, 구현 작업 목록, 라이브러리 선택을 반복해서 설명하지 않는다.

## 규범 용어

다음 한국어 용어를 일관되게 사용한다.

| 수준 | 표현 | 의미 |
|---|---|---|
| 필수 | `해야 한다` | 유효한 구현이라면 생략할 수 없다 |
| 금지 | `해서는 안 된다` | 유효한 구현이라면 수행할 수 없다 |
| 권장 | `권장한다` | 예외를 두려면 명시적 근거와 영향 검토가 필요하다 |
| 허용 | `할 수 있다` | 상호 운용성 또는 사용자 경험 영향을 정의한 선택 동작이다 |

주체나 권한 보유자가 불분명할 때 `가능하다`를 사용하지 않는다. 조건을 동작보다 먼저 쓴다.

## 필수 내용

승인된 정책에는 다음 중 관련 있는 내용을 포함한다.

1. 적용 범위와 비적용 범위
2. 용어 정의
3. 불변식
4. 상태 모델
5. 전이 규칙
6. 권한 매트릭스
7. 검증과 우선순위
8. 실패와 성능 저하 상태
9. 복구와 제한된 재시도
10. 보존과 삭제
11. 보안과 신뢰 경계
12. 예시와 반례
13. 관련 PRD 요구사항, 수용 기준, 결정
14. 승인을 막는 미결정 사항

## 규칙 품질

이슈에서 참조할 수 있는 모든 규칙 절에 전역으로 고유한 `POL-NN-R-NN` ID를 부여한다.

각 규칙에서 다음을 식별한다.

- 행위자 또는 시스템 구성요소
- 모든 전제 조건
- 허용하거나 요구하는 동작
- 결과 상태 또는 눈에 보이는 결과
- 실패 동작
- 되돌릴 수 있는지 여부
- 시간 경계가 있다면 그 경계

세 가지 이상의 사례가 같은 차원을 공유하면 상태 표나 권한 매트릭스를 우선 사용한다. 간결한 표에 담기 어려운 근거, 순서, 예외는 문장으로 설명한다.

승인된 정책에는 모든 `POL-NN-R-NN` 규칙을 완전한 PRD 요구사항 ID,
수용 기준 ID, 제품 결정 ID에 각각 하나 이상 연결하는 추적성 매트릭스를
포함한다. 이 역방향 연결을 통해 검토자는 단방향 PRD 링크에 의존하지 않고
규칙 변경의 영향을 받는 모든 제품 약속을 찾을 수 있다.

## 우선순위와 모순

두 규칙을 동시에 적용할 수 있다면 어느 규칙이 우선하는지 명시한다. 절 순서를 암묵적 우선순위로 사용하지 않는다.

정확한 규칙은 하나의 정책에만 기록한다. PRD와 다른 정책에서는 전체 문구를 복사하지 말고 제품 영향을 요약한 뒤 정본 규칙으로 연결한다.

## 실패와 재시도

한도를 정하지 않고 `계속 재시도한다`고 쓰지 않는다. 다음을 명시한다.

- 시도 횟수 제한
- 시간 제한
- 대기 전략 또는 새 세션의 시작 조건
- 한도를 소진한 뒤 사용자에게 보이는 상태
- 허용한다면 수동 복구 방법
