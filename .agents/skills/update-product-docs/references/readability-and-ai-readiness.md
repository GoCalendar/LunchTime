# 가독성과 AI 작업 준비도

다음 두 독자를 모두 고려해 문서를 최적화한다.

1. 결정을 빠르게 이해해야 하는 사람
2. 누락된 동작을 임의로 만들지 않고 구현해야 하는 AI 에이전트

## 사람이 읽기 쉬운 문서

- 한국어를 기본 작성 언어로 사용하되 자연스러운 표현과 정확한 의미 전달을 우선한다. 계약 ID, 경로, 명령, 기술 용어와 고유명사는 원문을 사용할 수 있다.
- 결론이나 규칙을 근거보다 먼저 쓴다.
- 가능하면 절마다 주제 하나, 문장마다 주동사 하나를 사용한다.
- 내용을 설명하면서 서로 평행한 제목을 사용한다.
- 번호 목록은 순서나 우선순위를 나타낼 때만 사용한다.
- 서로 독립적인 항목에는 글머리표를 사용한다.
- 실제로 두 차원의 비교나 매트릭스가 필요할 때만 표를 사용한다.
- 표 셀은 짧게 유지하고 여러 문단의 설명은 표 아래로 옮긴다.
- 용어는 한 번 정의하고 정확히 같은 표기를 재사용한다.
- 행위자를 명시한 직접적인 능동문을 우선 사용한다.
- 긴 절이 글의 벽처럼 보이기 전에 나눈다.
- `여기`나 원시 경로 대신 내용을 설명하는 링크 이름을 사용한다.

## AI 작업 준비도

- 전역으로 고유하고 변경되지 않는 계약 ID를 사용한다.
- 행위자, 전제 조건, 동작, 결과, 실패, 되돌릴 수 있는지 여부를 명시한다.
- 시간대, 경계, 단위, 경계값 포함 여부를 규칙에 명시한다.
- 관찰된 사실, 가정, 승인된 결정, 구현 제안을 구분한다.
- 편리한 기본값을 선택하지 말고 미결정 선택지를 미결정으로 표시한다.
- 모든 구현 이슈를 PRD 요구사항, 수용 기준, 정책 규칙으로 연결한다.
- 수용 여부를 검증할 수 있는 명령이나 근거를 명시한다.
- 제품 제약과 선택한 구현 방식을 분리한다.
- 여러 행위자나 객체를 가리킬 수 있을 때 대명사를 사용하지 않는다.

## 중복 검사

반복되는 모든 규칙에 다음을 묻는다.

1. 어느 문서가 정본인가?
2. 다른 문서에서 영향을 요약하고 정본으로 연결할 수 있는가?
3. 한 곳의 문구가 바뀌면 검토자가 갱신해야 할 다른 모든 곳을 확실히 알 수 있는가?

세 번째 질문의 답이 아니오라면 중복을 제거한다.

## 승인 검사

다음에 해당하면 문서를 승인하지 않는다.

- 자리표시자나 중요한 `TBD`가 남아 있다.
- 요구사항에 수용 판정 경로가 없다.
- 정책 규칙이 다른 정본 규칙과 충돌한다.
- 미결정 사항이 아키텍처나 사용자에게 보이는 동작을 바꿀 수 있다.
- 기준선이나 책임자 없이 성공 목표를 만들었다.
- 구현하려면 권한, 경계, 실패 결과를 여전히 추측해야 한다.
